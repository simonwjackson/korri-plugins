# Research: Dr. Mario 64 Recomp Plus on Linux

## Summary
The exact upstream has a Linux build path and explicit ARM64 shader-tool selection. Its private x86_64 engine build passed locally, and the native aarch64 build passed on the approved builder `fuji`. Owned-ROM startup, shutdown, restart, and persistence checks passed on both architectures. Physical-device gameplay remains unverified. A clean US retail ROM is required for generation and at runtime. Upstream warns it is "Very lightly tested overall."

Inspection date: 2026-10-02. The checked upstream commit is `af91e3bf56b1ffc329ff4327fdc2380515463de7`. Initial research inspected source only. Subsequent package and runtime results are recorded in `plugins/drmario64/README.md`.

## Findings

1. **Verified: Linux is a stated build target, not a verified release result.** README specifies C17/C++20, recommends Clang 15+, requires source-built SDL2 (example 2.26.1), and lists GTK3 development files. CMake requires 3.20 and links SDL2, FreeType, threads, `atomic`, and static libstdc++; it uses RT64 with an SDL Vulkan window. The README does not explain why SDL2 must be source-built. [README](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/README.md), [CMakeLists.txt](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/CMakeLists.txt)

   | Architecture | Direct source evidence | What remains unverified |
   |---|---|---|
   | Linux x86_64 | Main executable gets `-march=nehalem`; Linux DXC comes from `lib/rt64/src/contrib/dxc/bin/x64/dxc-linux` with matching library path. The private build and software-Vulkan Classic game board passed locally. | Physical GPU rendering, audible sound, controller mapping, and campaign save/reload. |
   | Linux aarch64 | Non-x86 branch omits `-march=nehalem` and selects `bin/arm64/dxc-linux` plus `lib/arm64`. Both pinned DXC files were checked with `readelf` and are AArch64 ELF64. `.gitmodules` includes `sse2neon`. | The private native build and owned-ROM runtime gates passed. The ARM screenshot shows the Classic setup menu. Full gameplay, RSP coverage beyond this path, and physical GPU acceptance remain unverified. |

2. **Verified: generation requires retail input and host tools.** README pins decomp `91dab37987bdad4d100958685cc10a011d4917dd` and N64Recomp `a13e5cff96686776b0e03baf23923e3c1927b770`. Decomp `make setup` produces `baserom_uncompressed.us.z64`, renamed to `drmario64_uncompressed.us.z64`. Both `N64Recomp drmario64.us.toml` and `RSPRecomp aspMain.us.toml` read it. CMake additionally runs `./N64Recomp patches.toml`, `file_to_c`, and patch `make`; the patch compiler targets MIPS with Clang/LLD. **Inference:** cross-building requires executable build-host generators, not merely target aarch64 tools. Cost: a private retail-input pipeline and dependency/toolchain work, not a simple public source-only build. [README](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/README.md), [game config](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/drmario64.us.toml), [RSP config](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/aspMain.us.toml), [patch Makefile](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/patches/Makefile)

3. **Verified: no ROM-path or direct-start CLI is implemented in `main`.** It explicitly discards `argc` and `argv`. The launcher opens a native file dialog, calls runtime `select_rom`, and starts the game from a UI event. With more than one detected controller it runs controller assignment first. The registered game is `drmario64.us`, internal name `DR.MARIO 64         `, hash constant `0x960e3703f29d996d`, save type `Eep4k`. Do not label this constant SHA-256 or assume its algorithm without inspecting the runtime. Runtime decompression callback is commented out and `has_compressed_code` is false with a TODO. Subsequent local tests booted the owner's clean US ROM through the patched native launcher and reached the Classic game board. [main.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/main/main.cpp), [ui_launcher.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/ui/ui_launcher.cpp)

4. **Verified: account isolation has an existing environment hook and a naming trap.** Linux app-folder precedence is `portable.txt` in current working directory → `APP_FOLDER_PATH` → `$HOME/.config/MarioKart64Recompiled` (passwd home fallback). It does not consult `XDG_CONFIG_HOME`. `main` registers this folder with the runtime. Application config writes `general.json`, `graphics.json`, `controls.json`, and `sound.json`, with backup helpers. **Recommendation:** use an account-owned `APP_FOLDER_PATH`, and avoid an unintended `portable.txt`; this avoids the inherited Mario Kart namespace. Cost: this alone does not prove all runtime save/mod paths or concurrent-session safety. Quicksaving is explicitly disabled. [config.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/game/config.cpp), [main.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/main/main.cpp), [quicksaving.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/game/quicksaving.cpp)

5. **Verified: native Linux assets are working-directory-relative.** Outside Flatpak, `get_program_path()` returns an empty path; assets resolve as `assets/...`, and `recompcontrollerdb.txt` resolves from the working directory. CMake copies `assets` and `icons` beside the executable but the inspected copy steps do not copy that controller database. A launcher must arrange the working directory and required files; an executable-only package is insufficient. **Recommendation:** an account-owned working directory with links to immutable assets can also contain mod writes. Cost: packaging must maintain those links; mod write behavior remains unaudited. [support.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/main/support.cpp), [main.cpp](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/src/main/main.cpp), [CMakeLists.txt](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/CMakeLists.txt)

6. **Verified: root `COPYING` contains GPL version 3.** Preserve license notices and meet corresponding-source obligations for distributed covered binaries. This document alone does not license Nintendo retail data or settle the status of generated game code, icons, or every dependency. **Recommendation:** keep ROMs and retail-derived build inputs out of public caches/packages pending an artifact and rights review. Cost: private builds and access controls; privacy itself does not establish distribution rights. [COPYING](https://github.com/theboy181/drmario64_recomp_plus/blob/af91e3bf56b1ffc329ff4327fdc2380515463de7/COPYING)

7. **Verified: the latest release contains one Windows archive.** The primary [release API](https://api.github.com/repos/theboy181/drmario64_recomp_plus/releases/latest) returned tag `1.0.0`, published December 18, 2025, with only `Dr.Mario.64.Recompiled-v1.0.0-Windows.zip`. No Linux asset is present in that release. This does not prove Linux source builds fail. [Release](https://github.com/theboy181/drmario64_recomp_plus/releases/tag/1.0.0)

## Gaps

| Blocker or decision | Required next step |
|---|---|
| **Private input authorization.** | Owner supplied the US ROM for local work. On 2026-10-03, the owner authorized private ARM64 build/test work on `fuji` once competing build activity stops. No public binary publication, signing, or device installation is authorized. |
| **Dependency audit.** | The recursive pinned sources were fetched over HTTPS without SSH credentials. Pinned ARM DXC executable and library headers are AArch64 ELF64. ARM build/runtime behavior and distribution rights still need separate evidence. |
| **Runtime layout grounding.** | Pinned `librecomp/src/recomp.cpp` defines `<game_id>.z64` and `pi.cpp` defines `saves/<game_id>.bin`, with 512 bytes for Eep4k. The plugin uses these native records. |
| **Direct launch integration.** | Both patched native packages passed direct-start tests through Core. `native-launch.patch` queues `--start` after the first VI. Earlier startup crashed before dummy-video initialization. |
| **Native shutdown.** | `native-shutdown.patch` parks game workers at IDLE, retains their process-lifetime memory, flushes persistence, and reports save failures. SIGTERM, ICCCM close, restart, two-account settings, and failed-save tests passed on both build machines. Cooperative IDLE remains required. |
| **Physical acceptance remains separate.** | Both architecture builds and clean-ROM startup checks passed, including two isolated accounts. Ask before device installation. Then verify its GPU, controllers, audible sound, full gameplay, and campaign save/reload. No device test was authorized or performed here. |

Additional issue, high importance: the inherited `MarioKart64Recompiled` state directory can mix unrelated applications' settings unless the launcher sets a dedicated path.
