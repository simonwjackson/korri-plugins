# Fable II on the Odin 2 Portal

The owner selected the online Odin for this test on 2026-10-03. The signed ARM64 plugin is installed and enabled. The actual packaged engine renders the Fable II title sequence fullscreen on Turnip Adreno 740 through Core's runtime-user sandbox. The owner reports "everything appears to work but framerate is not great" after the requested controls, movement and sound test. New native save files exist. Actual FPS, save reload and acceptable handheld performance remain unverified.

## Signed delivery and installation

Fuji's final package/check command passed in six seconds after a 90-second idle gate. Before the package pull, Fuji passed the same gate again. No Fable II build ran while other compiler jobs were active.

The first build-host pull failed because the engine carried Fuji's default signature, which the receiving build host did not trust. The existing `~/.config/korri/cache-key.secret` on Fuji matched that host's already-trusted `korri-cache-fuji-1` public key. Fuji added seven signatures to the existing private closure. The second pull passed without a signature bypass or trust-list change. No build or public upload ran.

The receiving build host exported the prebuilt closure into a private file cache with the existing personal publisher key. Its public key matched the Odin's existing `@simonwjackson` binding. Signing secrets stayed on their build hosts. The Odin's bound cache received new files without replacing existing entries.

Core's actual `inspect`, exact-digest `install`, and `enable` operations passed. Inspection declared no native services, ports or required plugins. Recursive `nix store verify --sigs-needed 1` passed. The effective policy stayed `max-jobs = 0`, empty `builders`, `fallback = false`, and `require-sigs = true`. The device compiled nothing and evaluated no flake.

After installation, hash comparisons confirmed unchanged publisher configuration, Nix configuration, existing catalog files, device configuration, and all prior plugin selections. The system generation stayed `/nix/store/f2w50achvn2xklzdckys34pz20a4qqn6-nixos-system-odin2portal-sd-card-26.05.20251221.a653104`. This test performed no firmware, boot-file, bootloader-state or partition-metadata write.

## Owner report and performance limits

In response to a request to try A, New Game, character selection, movement and speaker sound, the owner reported "everything appears to work but framerate is not great". This is owner-reported functional evidence, not an independently measured result for each requested action.

A later filesystem probe found new native save files under `B13EBABEBABEBABE/4D5307F1/00000001/Hero000/`, inside the account root. These include `mainsave.bin` at 130,458 bytes, `herosave.bin` at 1,513 bytes and `chaptersave.bin` at 507 bytes. The upstream save format and paths were unchanged. Creation is verified; loading those saves after a restart is not.

The final probe confirmed the exact native process still ran, temporary extraction files were removed, and the ISO retained its measured size.
