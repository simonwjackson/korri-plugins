# Zelda3 on the Mini V2

On 2026-10-02, the owner requested installation on the USB-connected Retroid
Pocket Mini V2. The signed ARM64 plugin was installed, enabled, added to the
library, and launched through korrid. A device screenshot showed the animated
Zelda intro. The owner confirmed that it worked well, then rebooted for an
unrelated reason.

## Post-reboot hidden-window correction

The owner later reported that the library entry failed to load. The native
process and runner were present. Sway showed the game window as hidden and
unfocused, with a 0x0 rectangle and no fullscreen state. The portal retained
fullscreen focus. This was a presentation failure, not failed ROM extraction.

A reversible compositor test made the exact game-owned window visible and
focused at 1240x1080. The persistent correction changed only `[Graphics]`
`Fullscreen = 0` to `Fullscreen = 1` in the account's native `zelda3.ini`.
The original file was backed up. Ownership, other settings, ROM, and saves
were preserved. At that point, package defaults and global compositor rules
remained unchanged. This correction applied to the existing Mini V2 account,
not fresh accounts or other devices. The package follow-up below changes the
fresh-profile default.

With the owner's permission, the current Super Mario World session was stopped
for verification. The test placed the portal fullscreen, then used Core's
`app.local-games.launch.selected` operation. The fresh Zelda3 window became
visible, focused, and fullscreen without any command to focus that new window.
A later check confirmed the same state and a screenshot showed the running
game's attract sequence. Zelda3 was left running.

The check tests actual compositor visibility as well as process identity.
A successful launch RPC or an `Enabled` plugin receipt alone cannot detect
this failure. No reboot was performed for this correction.

## Limits

The owner reported successful use. The agent did not independently verify
physical button response, audible sound, an in-game SRAM save, or full-game
completion. Opening controller descriptors is not proof of button response. Native snapshot save/reload passed earlier on both build
architectures, not on this device.

The shipped upstream code logged a Python escape-sequence warning during
extraction and an audio-library CPU-info warning. Neither prevented this launch.
No runtime code or upstream defaults were changed to suppress those warnings.

Installation used the existing private cache, not a public release. Another
device still needs a verified delivery route, publisher binding, and exact
permission approval. The generic commands remain in the plugin README.
